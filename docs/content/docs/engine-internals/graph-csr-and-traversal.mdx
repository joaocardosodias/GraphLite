Knowledge Graph exploration in embedded RAG requires expanding seed nodes across relational hops without pointer indirection stalls. Traditional pointer-based graph data structures (such as adjacency lists of heap pointers or B-Tree index lookups) cause frequent L1/L2 cache misses. Graphite resolves this by compressing graph topology into **Compressed Sparse Row (CSR)** flat memory buffers paired with a 1-cycle **DenseNodeBitSet** visited tracker.

---

## 1. Compressed Sparse Row (CSR) Adjacency Layout

The `CsrGraph` structure serializes the entire graph topology into two contiguous flat memory arrays:

```rust
// crates/graphite-core/src/graph/csr.rs
pub struct CsrGraph {
    /// Array of offsets into the edges array. Length is always node_count + 1.
    offsets: Vec<u64>,
    /// Contiguous array of all edges ordered by source node ID.
    edges: Vec<EdgeRecord>,
    /// Total number of nodes represented in this topology.
    node_count: usize,
}
```

### Memory Layout & Pointer-Free Indexing

For a graph with `N` nodes and `E` edges:

| Component | In-Memory Array | Byte Footprint | Purpose |
| :--- | :--- | :--- | :--- |
| **Row Offsets** | `offsets: Vec<u64>` | `(N + 1) * 8` bytes | Maps `NodeId(i)` to edge range `[offsets[i]..offsets[i+1]]` |
| **Edge Payload** | `edges: Vec<EdgeRecord>` | `E * 32` bytes | Contiguous array of 32-byte fixed `EdgeRecord` structs |

```text
Offsets Array (N = 4):
[0, 2, 5, 5, 7]
 │  │  │  │  └─ Node 3 edges end at index 7 (edges[5..7])
 │  │  │  └──── Node 2 has 0 edges (offsets[2] == offsets[3] == 5)
 │  │  └─────── Node 1 edges: edges[2..5] (3 outgoing edges)
 │  └────────── Node 0 edges: edges[0..2] (2 outgoing edges)
 └───────────── Start offset
```

### Constant Time O(1) Neighbor Lookup

To retrieve all outbound edges for any node in the database:

```rust
#[inline]
pub fn out_edges(&self, node_id: NodeId) -> &[EdgeRecord] {
    let idx = node_id.as_usize();
    if idx >= self.node_count || idx + 1 >= self.offsets.len() {
        return &[];
    }

    let start = self.offsets[idx] as usize;
    let end = self.offsets[idx + 1] as usize;

    if start > end || end > self.edges.len() {
        return &[];
    }

    &self.edges[start..end]
}
```

Because `out_edges` returns a direct subslice of contiguous memory, the CPU hardware prefetcher loads sequential `EdgeRecord` structs into L1 cache before the ALU processes them, resulting in zero pointer dereferences and zero heap allocations.

## 2. 1-Cycle Visited Tracking with DenseNodeBitSet

Traversing cyclic graphs requires tracking visited entities to prevent infinite loops and duplicate node evaluations. Using hash sets (`HashSet<NodeId>`) introduces hashing computation, bucket collisions, and dynamic heap resizing.

Graphite replaces hash sets with `DenseNodeBitSet`, packing visited flags into a dense array of 64-bit unsigned words (`u64`).

```rust
// crates/graphite-core/src/graph/traversal.rs
#[derive(Debug, Clone, Default)]
pub struct DenseNodeBitSet {
    words: Vec<u64>,
}

impl DenseNodeBitSet {
    #[inline]
    pub fn test_and_set(&mut self, node: NodeId) -> bool {
        let idx = node.as_u32() as usize;
        let word_idx = idx / 64;
        let bit_mask = 1u64 << (idx % 64);

        if word_idx >= self.words.len() {
            self.words.resize(word_idx + 1 + 16, 0);
        }

        let word = &mut self.words[word_idx];
        if (*word & bit_mask) != 0 {
            false // Already visited
        } else {
            *word |= bit_mask; // Mark as visited in 1 bitwise instruction
            true  // Newly visited
        }
    }
}
```

### Bitwise Operation Efficiency

Checking and marking a node executes in a single CPU cycle:
1. `word_idx = node_id >> 6` (Fast bit-shift division by 64).
2. `bit_mask = 1 << (node_id & 63)` (Fast bitwise AND modulo 64).
3. `test_and_set`: Evaluates `(*word & bit_mask) == 0` and applies `*word |= bit_mask`.

A database with 1,000,000 nodes requires only **122 Kilobytes of RAM** to track visited state across the entire graph.

## 3. Multi-Hop Relational BFS Engine

Breadth-First Search (BFS) explores relationships starting from vector and lexical seed nodes.

```rust
// crates/graphite-core/src/graph/traversal.rs
pub struct TraversalConfig {
    /// Maximum search depth in hops from seed nodes (e.g. 1, 2, or 3)
    pub max_depth: usize,
    /// Minimum edge weight threshold (edges below this are ignored)
    pub min_edge_weight: f32,
    /// Maximum unique nodes to visit (circuit breaker preventing graph explosion)
    pub max_nodes: usize,
    /// Traversal direction (Outgoing, Incoming, or Undirected)
    pub direction: TraversalDirection,
}
```

```rust
// Multi-hop BFS execution on immutable CSR topology
pub fn bfs_csr(
    csr: &CsrGraph,
    seeds: &[NodeId],
    config: &TraversalConfig,
) -> Vec<TraversedNode> {
    if seeds.is_empty() || config.max_nodes == 0 {
        return Vec::new();
    }

    let mut visited = DenseNodeBitSet::with_capacity(csr.node_count().max(seeds.len() * 8));
    let mut results: Vec<TraversedNode> = Vec::with_capacity(seeds.len() * 8);
    let mut queue: VecDeque<(NodeId, usize, Option<EdgeRecord>, f32)> =
        VecDeque::with_capacity(seeds.len() * 4);

    // Initialize seed nodes at depth 0
    for &seed in seeds {
        if visited.test_and_set(seed) {
            queue.push_back((seed, 0, None, 1.0));
            results.push(TraversedNode {
                node_id: seed,
                depth: 0,
                incoming_edge: None,
                path_weight: 1.0,
            });
        }
    }

    while let Some((current_node, current_depth, _, current_weight)) = queue.pop_front() {
        if current_depth >= config.max_depth {
            continue;
        }

        for edge in csr.out_edges(current_node) {
            if !edge.is_active() || edge.weight < config.min_edge_weight {
                continue;
            }

            let neighbor = edge.target;
            if visited.test_and_set(neighbor) {
                let path_weight = current_weight * edge.weight;
                let next_depth = current_depth + 1;

                results.push(TraversedNode {
                    node_id: neighbor,
                    depth: next_depth,
                    incoming_edge: Some(*edge),
                    path_weight,
                });

                if results.len() >= config.max_nodes {
                    return results;
                }

                queue.push_back((neighbor, next_depth, Some(*edge), path_weight));
            }
        }
    }

    results
}
```

## 4. Subgraph Extraction & Prompt Synthesis

Traversed nodes and their connecting edges are formatted into a directed relationship subgraph. This provides LLM prompts with grounded causal chains:

```text
[Direct Seed] Node A (Score: 0.92)
      │
      └─── [relates_to, weight: 0.85] ───► [1-Hop] Node B (Score: 0.78)
                                                │
                                                └─── [cites, weight: 0.90] ───► [2-Hop] Node C (Score: 0.70)
```

The resulting subgraph guarantees high semantic density while preventing ungrounded hallucination in downstream AI responses.
