A busca vetorial densa captura com eficácia a intenção semântica global, mas possui pontos cegos ao lidar com correspondências exatas de termos, identificadores de código, números de artigos de lei e siglas de domínio. O Graphite resolve essa limitação unificando projeções vetoriais densas com um índice invertido BM25 em memória por meio de **Reciprocal Rank Fusion (RRF)** e pontuação estrutural em grafo com decaimento exponencial por profundidade.

---

## 1. Índice Léxico Invertido BM25

O Graphite indexa nomes, tipos e descrições das entidades em um índice invertido em memória com suporte ao algoritmo de ranqueamento Okapi BM25.

```rust
// crates/graphite-core/src/graph/bm25.rs
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Bm25Params {
    /// Parâmetro de saturação da frequência do termo (padrão: 1.2)
    pub k1: f32,
    /// Parâmetro de normalização pelo tamanho do documento (padrão: 0.75)
    pub b: f32,
}

#[derive(Debug, Clone, Default)]
pub struct Bm25Index {
    inverted_index: HashMap<String, Vec<(NodeId, u32)>>,
    doc_lengths: HashMap<NodeId, usize>,
    total_tokens: usize,
    params: Bm25Params,
}
```

### Formulação Matemática da Pontuação

Para uma consulta `Q` contendo os termos `t_1, t_2, ..., t_m` e um nó de documento candidato `D`, a pontuação BM25 é calculada por:

```text
Score(D, Q) = soma( IDF(t) * ( (TF(t, D) * (k1 + 1)) / (TF(t, D) + k1 * (1 - b + b * (|D| / avgdl))) ) )
```

Onde:
* `TF(t, D)` é a frequência do termo `t` no documento `D`.
* `|D|` é a contagem de tokens do documento `D`.
* `avgdl` é a média de tokens por documento em todo o grafo indexado.
* `k1 = 1.2` calibra o limite de saturação da repetição do termo.
* `b = 0.75` controla a penalidade imposta a documentos excessivamente longos.

A Frequência Inversa de Documento (`IDF`) utiliza a formulação de Robertson-Spärck Jones:

```text
IDF(t) = ln( 1.0 + (N - DF(t) + 0.5) / (DF(t) + 0.5) )
```

Onde `N` representa a quantidade total de nós indexados e `DF(t)` é a quantidade de documentos que contêm o termo `t`.

## 3. Fusão por Postos Recíprocos (RRF)

A busca vetorial densa gera pontuações contínuas de cosseno em `[-1.0, 1.0]`, enquanto o BM25 produz pontuações léxicas positivas não-limitadas em `[0.0, +inf)`. A simples soma desses valores brutos geraria distorções severas de escala.

O Graphite unifica os rankings aplicando o algoritmo **Reciprocal Rank Fusion (RRF)**:

```text
Score_RRF(d) = soma( 1.0 / (k + posto_r(d)) )  para r em Rankings
```

Onde `posto_r(d)` é a posição ordinal (iniciando em 1) do candidato `d` na lista ranqueada `r` (Vetorial ou BM25), e `k = 60` é o fator de suavização padrão que impede que itens no topo de uma única lista dominem desproporcionalmente o resultado.

```rust
// crates/graphite-core/src/graph/hybrid_score.rs
pub fn compute_rrf_fused_ranks(
    ranked_lists: &[&[(NodeId, f32)]],
    k: usize,
) -> HashMap<NodeId, f32> {
    let mut rrf_scores: HashMap<NodeId, f32> = HashMap::new();
    let k_f32 = k as f32;

    for list in ranked_lists {
        for (rank_idx, (node_id, _)) in list.iter().enumerate() {
            let rank = (rank_idx + 1) as f32;
            let score_increment = 1.0 / (k_f32 + rank);
            *rrf_scores.entry(*node_id).or_insert(0.0) += score_increment;
        }
    }

    // Normalização dos scores RRF para a faixa [0.0, 1.0]
    let max_possible = ranked_lists.len() as f32 / (k_f32 + 1.0);
    if max_possible > 0.0 {
        for score in rrf_scores.values_mut() {
            *score = (*score / max_possible).clamp(0.0, 1.0);
        }
    }

    rrf_scores
}
```

## 4. Pontuação Híbrida em Grafo & Decaimento por Profundidade

Os nós descobertos via busca vetorial e léxica atuam como **nós semente** (*seed nodes*) para a expansão relacional no grafo. À medida que a busca em largura (BFS) avança pelos relacionamentos, os pesos estruturais decaem exponencialmente com a profundidade.

### Configuração de Pontuação

```rust
// crates/graphite-core/src/graph/hybrid_score.rs
pub struct HybridScoreConfig {
    pub alpha: f32,                // Peso Vetorial vs Estrutura do Grafo (padrão: 0.6)
    pub depth_decay: f32,          // Fator de decaimento por salto (padrão: 0.85)
    pub min_score_threshold: f32,  // Limiar mínimo de corte (padrão: 0.05)
    pub use_rrf: bool,             // Ativar fusão RRF (padrão: true)
    pub rrf_k: usize,              // Constante de suavização (padrão: 60)
}
```

### Fórmula de Pontuação Combinada

Para um nó `d` alcançado a uma distância `depth` através da aresta incidente `e`:

```text
PontuacaoFinal(d) = alpha * ScoreSemente(d) + (1 - alpha) * ( PesoAresta(e) * (depth_decay ^ depth) )
```

### Tabela de Impacto do Decaimento por Profundidade

| Profundidade da Travessia | Fator de Decaimento (`gamma = 0.85`) | Multiplicador do Peso Estrutural |
| :--- | :--- | :--- |
| **Profundidade 0 (Semente Direta)** | $0.85^0 = 1.0000$ | 100.0% do peso da aresta |
| **Profundidade 1 (Vizinho a 1 Salto)**| $0.85^1 = 0.8500$ | 85.0% do peso da aresta |
| **Profundidade 2 (Vizinho a 2 Saltos)**| $0.85^2 = 0.7225$ | 72.25% do peso da aresta |
| **Profundidade 3 (Vizinho a 3 Saltos)**| $0.85^3 = 0.6141$ | 61.41% do peso da aresta |

Entidades com pontuação abaixo de `min_score_threshold` (0.05) são podadas antes da síntese do contexto, assegurando que nenhum orçamento de tokens seja desperdiçado com nós distantes ou ruídos estruturais.
