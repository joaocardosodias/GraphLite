A recuperação de primeiro estágio (similaridade vetorial SIMD e busca léxica BM25) filtra rapidamente milhões de entidades para algumas dezenas de candidatos mais promissores. No entanto, arquiteturas Bi-Encoder codificam a consulta e os documentos de forma independente, sacrificando as interações detalhadas de atenção cruzada entre cada par de tokens.

O Graphite incorpora um **Reranker Local Cross-Encoder** baseado no modelo `bge-reranker-base`, executado nativamente pelo ONNX Runtime em Rust puro, fornecendo pontuação de relevância semântica profunda sem necessidade de servidores externos em Python.

---

## 1. Comparativo Arquitetural: Bi-Encoder vs Cross-Encoder

| Dimensão | Bi-Encoder (Recuperação de 1º Estágio) | Cross-Encoder (Reranking de 2º Estágio) |
| :--- | :--- | :--- |
| **Formato de Entrada** | Codificados separadamente: `E(Q)` e `E(D)` | Concatenados: `[CLS] Consulta [SEP] Documento [SEP]` |
| **Mecanismo de Atenção**| Auto-atenção apenas intra-sequência | Atenção cruzada total todos-para-todos entre os tokens |
| **Custo Computacional** | $O(D)$ produto escalar por candidato | $O(L^2)$ avaliações completas de camadas Transformer |
| **Taxa de Processamento**| Mais de 500.000 candidatos/s via SIMD AVX2 | 50 a 500 candidatos/s por thread de CPU |
| **Precisão Semântica** | Moderada (Captura o tema semântico geral) | Altíssima (Captura sintaxe, negações e condições lógicas) |

## 2. Motor de Inferência ONNX em Processo (`LocalReranker`)

O Graphite executa o modelo de Cross-Encoder diretamente no espaço de endereçamento da aplicação, eliminando a sobrecarga de comunicação entre processos (IPC) e latências de rede HTTP.

```rust
// crates/graphite-core/src/vector/reranker.rs
pub struct LocalReranker {
    #[cfg(feature = "fastembed")]
    model: Mutex<TextRerank>,
}

impl LocalReranker {
    /// Inicializa a instância local do reranker com bge-reranker-base
    #[cfg(feature = "fastembed")]
    pub fn new_bge_base() -> Result<Self> {
        let mut options = RerankInitOptions::default();
        options.model_name = RerankerModel::BGERerankerBase;
        options.show_download_progress = false;

        let model = TextRerank::try_new(options)
            .map_err(|e| GraphiteError::Io(std::io::Error::other(e.to_string())))?;

        Ok(Self {
            model: Mutex::new(model),
        })
    }

    /// Re-ranqueia fatias de texto candidatas em relação à consulta de entrada
    #[cfg(feature = "fastembed")]
    pub fn rerank<S: AsRef<str>>(&self, query: &str, documents: &[S]) -> Result<Vec<RerankResult>> {
        if documents.is_empty() {
            return Ok(Vec::new());
        }

        let doc_strs: Vec<&str> = documents.iter().map(|s| s.as_ref()).collect();
        let mut guard = self.model.lock();

        let results = guard
            .rerank(query, doc_strs, true, None)
            .map_err(|e| GraphiteError::Io(std::io::Error::other(e.to_string())))?;

        let mapped = results
            .into_iter()
            .map(|r| RerankResult {
                index: r.index,
                score: sigmoid(r.score),
                raw_score: r.score,
            })
            .collect();

        Ok(mapped)
    }
}
```

## 3. Normalização de Logits & Calibração por Sigmoid

A rede neural gera logits reais não-limitados `z` na faixa `(-inf, +inf)`. Para unificar a pontuação do reranker com a topologia do grafo e aplicar filtros consistentes por limiar de confiança, os logits são normalizados pela **função Sigmoid**:

```text
sigma(z) = 1.0 / (1.0 + exp(-z))
```

```rust
#[inline]
pub fn sigmoid(x: f32) -> f32 {
    1.0 / (1.0 + (-x).exp())
}
```

### Comportamento de Calibração

| Logit Bruto (`z`) | Probabilidade Normalizada (`sigma(z)`) | Interpretação Prática |
| :--- | :--- | :--- |
| `+4.00` | `0.9820` | Correspondência semântica definitiva |
| `+2.00` | `0.8808` | Alta relevância contextual |
| `0.00` | `0.5000` | Linha de base neutra / ambígua |
| `-0.49` | `0.3800` | Conexão semântica fraca |
| `-7.59` | `0.0005` | Candidato irrelevante ou contraditório |

## 4. Pipeline de Recuperação de Dois Estágios Ponta a Ponta

<Steps>
<Step>
### Estágio 1: Geração Rápida de Candidatos
* **Varredura Vetorial SIMD AVX2:** Busca os Top-K nós mais próximos no espaço semântico em sub-microssegundos.
* **Varredura Léxica BM25:** Identifica termos exatos, números de artigos de lei e identificadores de código.
* **Reciprocal Rank Fusion (RRF):** Unifica as duas listas ordenadas com fator de amortecimento $k=60$.
* **Travessia Relacional em Grafo CSR:** Expande os nós semente por saltos multi-hop $O(1)$.
</Step>

<Step>
### Estágio 2: Reranking Profundo com Cross-Encoder
* **Atenção Cruzada em Nível de Token:** Execução local do modelo transformer `bge-reranker-base` via ONNX Runtime.
* **Calibração por Sigmoid:** Normalização dos logits $\sigma(z) \in [0.0, 1.0]$.
* **Poda por Limiar de Confiança:** Descarte antecipado de candidatos com baixa probabilidade semântica.
</Step>

<Step>
### Estágio 3: Síntese de Contexto & Imposição de Orçamento
* **Otimização por Diversidade (MMR):** Elimina passagens redundantes com similaridade de Jaccard zero-alocação ($\lambda = 0.75$).
* **Poda Exata de Tokens com BPE Tiktoken:** Montagem do contexto Markdown garantindo conformidade estrita com o limite do LLM.
</Step>
</Steps>
