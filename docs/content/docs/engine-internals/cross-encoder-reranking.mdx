First-stage retrieval (SIMD vector similarity and BM25 lexical indexing) rapidly narrows millions of candidates down to the top dozens. However, bi-encoder architectures encode query and document strings independently, sacrificing granular token-to-token cross-attention interactions.

Graphite incorporates an in-process **Local Cross-Encoder Reranker** powered by `bge-reranker-base` executing through the ONNX Runtime in pure Rust, providing deep semantic relevance scoring with zero external Python services.

---

## 1. Architectural Comparison: Bi-Encoder vs Cross-Encoder

| Dimension | Bi-Encoder (1st Stage Retrieval) | Cross-Encoder (2nd Stage Reranking) |
| :--- | :--- | :--- |
| **Input Format** | Encoded independently: `E(Q)` and `E(D)` | Concatenated: `[CLS] Query [SEP] Document [SEP]` |
| **Attention Mechanism** | Intra-sequence self-attention only | Full all-to-all cross-attention across all tokens |
| **Computational Complexity**| $O(D)$ vector cosine distance per candidate | $O(L^2)$ Transformer layer evaluations |
| **Throughput & Speed** | 500,000+ candidates/sec via SIMD AVX2 | 50 – 500 candidates/sec per CPU thread |
| **Semantic Precision** | Moderate (Captures broad topic similarity) | Very High (Captures syntax, negation, fine details) |

## 2. In-Process ONNX Inference Engine (`LocalReranker`)

Graphite executes the Cross-Encoder model directly within the calling application process, eliminating inter-process communication (IPC) and HTTP latency.

```rust
// crates/graphite-core/src/vector/reranker.rs
pub struct LocalReranker {
    #[cfg(feature = "fastembed")]
    model: Mutex<TextRerank>,
}

impl LocalReranker {
    /// Initializes a local reranker instance with bge-reranker-base
    #[cfg(feature = "fastembed")]
    pub fn new_bge_base() -> Result<Self> {
        let mut options = RerankInitOptions::default();
        options.model_name = RerankerModel::BGERerankerBase;
        options.show_download_progress = false;

        let model = TextRerank::try_new(options)
            .map_err(|e| GraphiteError::Io(std::io::Error::other(e.to_string())))?;

        Ok(Self {
            model: Mutex::new(model),
        })
    }

    /// Reranks candidate document strings against the input query
    #[cfg(feature = "fastembed")]
    pub fn rerank<S: AsRef<str>>(&self, query: &str, documents: &[S]) -> Result<Vec<RerankResult>> {
        if documents.is_empty() {
            return Ok(Vec::new());
        }

        let doc_strs: Vec<&str> = documents.iter().map(|s| s.as_ref()).collect();
        let mut guard = self.model.lock();

        let results = guard
            .rerank(query, doc_strs, true, None)
            .map_err(|e| GraphiteError::Io(std::io::Error::other(e.to_string())))?;

        let mapped = results
            .into_iter()
            .map(|r| RerankResult {
                index: r.index,
                score: sigmoid(r.score),
                raw_score: r.score,
            })
            .collect();

        Ok(mapped)
    }
}
```

## 3. Logit Normalization & Sigmoid Calibration

The neural network outputs unconstrained real-valued logits `z` in `(-inf, +inf)`. To fuse reranking output with graph topology scores and apply consistent threshold filters, logits are normalized via the **Sigmoid function**:

```text
sigma(z) = 1.0 / (1.0 + exp(-z))
```

```rust
#[inline]
pub fn sigmoid(x: f32) -> f32 {
    1.0 / (1.0 + (-x).exp())
}
```

### Calibration Behavior

| Raw Logit (`z`) | Normalized Probability (`sigma(z)`) | Interpretation |
| :--- | :--- | :--- |
| `+4.00` | `0.9820` | Definitive semantic match |
| `+2.00` | `0.8808` | Strong contextual relevance |
| `0.00` | `0.5000` | Neutral / ambiguous baseline |
| `-0.49` | `0.3800` | Weak semantic connection |
| `-7.59` | `0.0005` | Irrelevant / negative candidate |

## 4. End-to-End Two-Stage Retrieval Pipeline

<Steps>
<Step>
### Stage 1: Fast Candidate Generation
* **SIMD AVX2 Vector Scan:** Sub-microsecond dense cosine search over memory-mapped quantized embeddings.
* **Inverted Index BM25 Scan:** Fast lexical matching for exact keywords, statutes, and code identifiers.
* **Reciprocal Rank Fusion (RRF):** Fuses dense and sparse rankings with smoothing constant $k=60$.
* **CSR Relational Graph Traversal:** Multi-hop BFS expanding seed nodes across relational hops in $O(1)$ time.
</Step>

<Step>
### Stage 2: Deep Cross-Encoder Reranking
* **Token-Level Cross-Attention:** Direct token-to-token cross-attention using `bge-reranker-base` in ONNX Runtime.
* **Sigmoid Probability Normalization:** Maps raw logits to calibrated probabilities $\sigma(z) \in [0.0, 1.0]$.
* **Confidence Threshold Pruning:** Prunes weak candidates prior to prompt assembly.
</Step>

<Step>
### Stage 3: Synthesis & Context Budget Enforcement
* **MMR Diversity Optimization:** Eliminates semantic redundancies with zero-allocation Jaccard similarity ($\lambda = 0.75$).
* **Exact Token Budget Packing:** Assembles the final Markdown context strictly conforming to the LLM token budget via Tiktoken BPE.
</Step>
</Steps>
