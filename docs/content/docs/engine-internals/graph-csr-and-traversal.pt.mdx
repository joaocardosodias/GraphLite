A exploração de Grafos de Conhecimento em arquiteturas GraphRAG embarcadas exige a expansão dos nós semente através de saltos relacionais sem paradas no *pipeline* causadas por descontinuidade de memória. Estruturas tradicionais baseadas em ponteiros (como listas de adjacência encadeadas no heap ou árvores B) geram constantes *cache misses* nos níveis L1 e L2 da CPU. O Graphite resolve esse gargalo compactando a topologia do grafo em buffers contíguos no formato **Compressed Sparse Row (CSR)**, combinados com um rastreador de nós visitados em 1 ciclo de clock via **DenseNodeBitSet**.

---

## 1. Layout de Adjacência em Compressed Sparse Row (CSR)

A estrutura `CsrGraph` serializa toda a topologia de conexões do grafo em dois arrays contíguos de memória:

```rust
// crates/graphite-core/src/graph/csr.rs
pub struct CsrGraph {
    /// Array de offsets para o array de arestas. Tamanho é sempre node_count + 1.
    offsets: Vec<u64>,
    /// Array contíguo com todas as arestas ordenadas pelo ID do nó de origem.
    edges: Vec<EdgeRecord>,
    /// Quantidade total de nós representados nesta topologia.
    node_count: usize,
}
```

### Layout de Memória & Indexação Sem Ponteiros

Para um grafo contendo `N` nós e `E` arestas:

| Componente | Array em Memória | Pegada em Bytes | Finalidade |
| :--- | :--- | :--- | :--- |
| **Offsets de Linha** | `offsets: Vec<u64>` | `(N + 1) * 8` bytes | Mapeia `NodeId(i)` para a faixa de arestas `[offsets[i]..offsets[i+1]]` |
| **Carga de Arestas** | `edges: Vec<EdgeRecord>` | `E * 32` bytes | Array contíguo de registros fixos `EdgeRecord` (32 bytes) |

```text
Array de Offsets (N = 4):
[0, 2, 5, 5, 7]
 │  │  │  │  └─ Arestas do Nó 3 terminam no índice 7 (edges[5..7])
 │  │  │  └──── Nó 2 possui 0 arestas (offsets[2] == offsets[3] == 5)
 │  │  └─────── Arestas do Nó 1: edges[2..5] (3 arestas de saída)
 │  └────────── Arestas do Nó 0: edges[0..2] (2 arestas de saída)
 └───────────── Offset inicial
```

### Busca de Vizinhos em Tempo Constante O(1)

Para recuperar todas as arestas que saem de qualquer nó do banco:

```rust
#[inline]
pub fn out_edges(&self, node_id: NodeId) -> &[EdgeRecord] {
    let idx = node_id.as_usize();
    if idx >= self.node_count || idx + 1 >= self.offsets.len() {
        return &[];
    }

    let start = self.offsets[idx] as usize;
    let end = self.offsets[idx + 1] as usize;

    if start > end || end > self.edges.len() {
        return &[];
    }

    &self.edges[start..end]
}
```

Como `out_edges` retorna uma fatia direta de memória contígua, o mecanismo de *hardware prefetching* da CPU carrega os registros sequenciais `EdgeRecord` para o cache L1 antes mesmo que a ALU processe suas instruções, resultando em **zero desreferenciações de ponteiro** e **zero alocações no heap**.

## 2. Rastreamento de Visitas em 1 Ciclo com DenseNodeBitSet

Percorrer grafos cíclicos exige o rastreamento rigoroso das entidades visitadas para prevenir loops infinitos e avaliações redundantes. O uso de tabelas hash (`HashSet<NodeId>`) introduz sobrecarga computacional de hashing, colisões de buckets e realocações dinâmicas de heap.

O Graphite substitui tabelas hash pelo `DenseNodeBitSet`, compactando os bits de estado em um array contíguo de palavras de 64 bits (`u64`).

```rust
// crates/graphite-core/src/graph/traversal.rs
#[derive(Debug, Clone, Default)]
pub struct DenseNodeBitSet {
    words: Vec<u64>,
}

impl DenseNodeBitSet {
    #[inline]
    pub fn test_and_set(&mut self, node: NodeId) -> bool {
        let idx = node.as_u32() as usize;
        let word_idx = idx / 64;
        let bit_mask = 1u64 << (idx % 64);

        if word_idx >= self.words.len() {
            self.words.resize(word_idx + 1 + 16, 0);
        }

        let word = &mut self.words[word_idx];
        if (*word & bit_mask) != 0 {
            false // Já visitado
        } else {
            *word |= bit_mask; // Marca como visitado em 1 instrução bit a bit
            true  // Recém-visitado
        }
    }
}
```

### Eficiência das Operações Bit a Bit

A verificação e marcação de um nó executa em 1 único ciclo de clock:
1. `word_idx = node_id >> 6` (Divisão rápida por 64 via bit-shift).
2. `bit_mask = 1 << (node_id & 63)` (Operação rápida de resto por 64 via bitwise AND).
3. `test_and_set`: Avalia `(*word & bit_mask) == 0` e aplica `*word |= bit_mask`.

Um banco contendo 1.000.000 de nós exige apenas **122 Kilobytes de RAM** para rastrear o estado de visita de todo o grafo.

## 3. Motor de Busca em Largura (BFS) Relacional Multi-Hop

A busca em largura (*Breadth-First Search*) explora os relacionamentos a partir dos nós semente descobertos pelas buscas vetorial e léxica.

```rust
// crates/graphite-core/src/graph/traversal.rs
pub struct TraversalConfig {
    /// Profundidade máxima de busca em saltos a partir dos nós semente (ex: 1, 2 ou 3)
    pub max_depth: usize,
    /// Limiar mínimo de peso de aresta (arestas com peso abaixo são ignoradas)
    pub min_edge_weight: f32,
    /// Quantidade máxima de nós únicos a visitar (circuit-breaker contra explosão do grafo)
    pub max_nodes: usize,
    /// Direção da travessia (Outgoing, Incoming ou Undirected)
    pub direction: TraversalDirection,
}
```

```rust
// Execução do BFS multi-hop sobre a topologia CSR imutável
pub fn bfs_csr(
    csr: &CsrGraph,
    seeds: &[NodeId],
    config: &TraversalConfig,
) -> Vec<TraversedNode> {
    if seeds.is_empty() || config.max_nodes == 0 {
        return Vec::new();
    }

    let mut visited = DenseNodeBitSet::with_capacity(csr.node_count().max(seeds.len() * 8));
    let mut results: Vec<TraversedNode> = Vec::with_capacity(seeds.len() * 8);
    let mut queue: VecDeque<(NodeId, usize, Option<EdgeRecord>, f32)> =
        VecDeque::with_capacity(seeds.len() * 4);

    // Inicialização dos nós semente na profundidade 0
    for &seed in seeds {
        if visited.test_and_set(seed) {
            queue.push_back((seed, 0, None, 1.0));
            results.push(TraversedNode {
                node_id: seed,
                depth: 0,
                incoming_edge: None,
                path_weight: 1.0,
            });
        }
    }

    while let Some((current_node, current_depth, _, current_weight)) = queue.pop_front() {
        if current_depth >= config.max_depth {
            continue;
        }

        for edge in csr.out_edges(current_node) {
            if !edge.is_active() || edge.weight < config.min_edge_weight {
                continue;
            }

            let neighbor = edge.target;
            if visited.test_and_set(neighbor) {
                let path_weight = current_weight * edge.weight;
                let next_depth = current_depth + 1;

                results.push(TraversedNode {
                    node_id: neighbor,
                    depth: next_depth,
                    incoming_edge: Some(*edge),
                    path_weight,
                });

                if results.len() >= config.max_nodes {
                    return results;
                }

                queue.push_back((neighbor, next_depth, Some(*edge), path_weight));
            }
        }
    }

    results
}
```

## 4. Extração de Subgrafos & Síntese de Prompts

Os nós percorridos e suas arestas de conexão são organizados em um subgrafo relacional direcionado, fornecendo ao LLM cadeias causais fundamentadas:

```text
[Semente Direta] Nó A (Score: 0.92)
      │
      └─── [relates_to, peso: 0.85] ───► [1 Salto] Nó B (Score: 0.78)
                                                │
                                                └─── [cites, peso: 0.90] ───► [2 Saltos] Nó C (Score: 0.70)
```

O subgrafo resultante assegura alta densidade de contexto, eliminando alucinações nas respostas geradas por agentes de IA.
