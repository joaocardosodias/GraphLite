O formato de arquivo `.graphite` é um banco de dados binário contíguo de arquivo único projetado para leituras zero-copy de altíssimo rendimento via mapeamento de memória (`mmap`). Todos os registros de grafo, embeddings vetoriais, topologias de adjacência e tabelas de strings são organizados sequencialmente com alinhamento estrito de 64 bits e 32 bytes para prevenir penalidades de acesso à memória desalinhada em processadores x86_64 e ARM64.

---

## Visão Geral do Layout em Disco

Um arquivo binário `.graphite` consiste em um cabeçalho fixo de 64 bytes seguido por quatro seções contíguas com offsets independentes:

| Faixa de Bytes | Nome da Seção | Conteúdo |
| :--- | :--- | :--- |
| `0x0000 .. 0x0040` | **Database Header** | Magic bytes, versão, dimensões, offsets das seções e checksum CRC32 |
| `0x0040 .. OffsetE` | **Node Block** | Array contíguo de registros fixos `NodeRecord` (32 bytes) |
| `OffsetE .. OffsetV` | **Edge / CSR Block** | Ponteiros de linha CSR e registros fixos `EdgeRecord` (32 bytes) |
| `OffsetV .. OffsetS` | **Vector Block** | Matriz vetorial densa Float32 ou quantizada em Int8 (SQ8) |
| `OffsetS .. EOF` | **String Interner Pool** | Fatias de string UTF-8 com prefixo de tamanho e índice O(1) |

---

## 1. Cabeçalho Fixo de 64 Bytes (`GraphHeader`)

Todo arquivo `.graphite` inicia com um cabeçalho de 64 bytes (`#[repr(C)]`), garantindo que a seção subsequente `NodeBlock` inicie no offset exato de byte `0x00000040` (64 decimal), correspondente ao tamanho padrão de uma linha de cache L1 de CPU.

### Tabela de Layout Binário

| Offset de Byte | Nome do Campo | Tipo | Descrição |
| :--- | :--- | :--- | :--- |
| `0x00 .. 0x04` | `magic` | `[u8; 4]` | Magic bytes ASCII: `b"GRPH"` (`0x47, 0x52, 0x50, 0x48`). |
| `0x04 .. 0x06` | `version` | `u16` | Versão da especificação binária (`1`). |
| `0x06 .. 0x08` | `flags` | `u16` | Bitflags de recursos (`0x01`: Quantizado SQ8, `0x02`: Comprimido, `0x04`: Direcionado). |
| `0x08 .. 0x0A` | `vector_dim` | `u16` | Dimensão dos vetores de embedding (ex: `384`, `768`, `1536`). |
| `0x0A .. 0x0B` | `metric_type` | `u8` | Métrica de distância (`0`: Cosseno, `1`: Produto Escalar, `2`: Euclidiana, `3`: Manhattan). |
| `0x0B .. 0x0C` | `quant_type` | `u8` | Formato de armazenamento do vetor (`0`: Float32, `1`: Quantização Escalar Int8). |
| `0x0C .. 0x10` | `node_count` | `u32` | Quantidade total de nós ativos. |
| `0x10 .. 0x14` | `edge_count` | `u32` | Quantidade total de arestas ativas. |
| `0x14 .. 0x18` | `string_bytes_len`| `u32` | Tamanho total em bytes do pool de strings. |
| `0x18 .. 0x20` | `node_section_offset` | `u64` | Offset de byte onde o `NodeBlock` inicia. |
| `0x20 .. 0x28` | `edge_section_offset` | `u64` | Offset de byte onde o `CSRBlock` inicia. |
| `0x28 .. 0x30` | `vector_section_offset`| `u64` | Offset de byte onde o `VectorBlock` inicia. |
| `0x30 .. 0x38` | `string_section_offset`| `u64` | Offset de byte onde o `StringTable` inicia. |
| `0x38 .. 0x3C` | `checksum` | `u32` | Checksum polinomial CRC32 IEEE 802.3 calculado sobre o arquivo. |
| `0x3C .. 0x40` | `_reserved` | `[u8; 4]` | Preenchimento de alinhamento estrutural para 64 bytes. |

### Estrutura Rust do Header

```rust
#[repr(C)]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct GraphHeader {
    pub magic: [u8; 4],
    pub version: u16,
    pub flags: u16,
    pub vector_dim: u16,
    pub metric_type: u8,
    pub quant_type: u8,
    pub node_count: u32,
    pub edge_count: u32,
    pub string_bytes_len: u32,
    pub node_section_offset: u64,
    pub edge_section_offset: u64,
    pub vector_section_offset: u64,
    pub string_section_offset: u64,
    pub checksum: u32,
    pub _reserved: [u8; 4],
}
```

## 2. Bloco de Nós & Estrutura de Registros

O `NodeBlock` armazena um array contíguo de registros de tamanho fixo de 32 bytes. Como dados de texto de tamanho variável (rótulos, descrições, tipos) são armazenados no pool de strings através de identificadores `StringId` de 32 bits, cada `NodeRecord` tem tamanho estritamente determinístico:

```rust
#[repr(C)]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct NodeRecord {
    pub id: NodeId,               // 4 bytes (u32)
    pub name_id: StringId,         // 4 bytes (u32)
    pub type_id: StringId,         // 4 bytes (u32)
    pub description_id: StringId,  // 4 bytes (u32)
    pub vector_offset: u64,        // 8 bytes (u64)
    pub flags: u32,                // 4 bytes (u32, bit 0 = FLAG_ACTIVE)
    pub _reserved: u32,            // 4 bytes (padding de alinhamento para 8 bytes)
}
```

### Custo de Acesso e Alinhamento de Memória

* **Tamanho do Registro:** Exatamente 32 bytes (`std::mem::size_of::<NodeRecord>() == 32`).
* **Acesso Aleatório:** Acessar o nó no índice `i` exige calcular:
  `Offset(i) = node_section_offset + 8 + (i * 32)`
* **Complexidade Temporal:** O(1) via aritmética direta de ponteiros sobre a fatia mmap, sem desserialização intermediária.

## 3. Bloco de Topologia em Compressed Sparse Row (CSR)

O Graphite serializa a conectividade do grafo utilizando o formato **Compressed Sparse Row (CSR)**, eliminando ponteiros encadeados, descontinuidades na memória e sobrecarga de alocações fragmentadas.

### Representação Binária

| Nome do Campo | Tipo / Tamanho | Descrição |
| :--- | :--- | :--- |
| `node_count` | `u32` (4 bytes) | Total de nós ativos no grafo ($N$) |
| `edge_count` | `u32` (4 bytes) | Total de arestas ativas no grafo ($E$) |
| `row_offsets` | `[u64; N + 1]` ($(N + 1) \times 8$ bytes) | Ponteiros de início e fim das arestas de saída de cada nó |
| `edges` | `[EdgeRecord; E]` ($E \times 32$ bytes) | Array contíguo de descritores de aresta de 32 bytes |

### Estrutura `EdgeRecord` (32 Bytes)

```rust
#[repr(C)]
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct EdgeRecord {
    pub id: EdgeId,                // 4 bytes (u32)
    pub source: NodeId,            // 4 bytes (u32)
    pub target: NodeId,            // 4 bytes (u32)
    pub relation_id: StringId,     // 4 bytes (u32)
    pub weight: f32,               // 4 bytes (f32)
    pub flags: u32,                // 4 bytes (u32, bit 0 = ACTIVE, bit 1 = DIRECTED)
    pub _reserved: u64,            // 8 bytes (padding para alinhamento a 64 bits)
}
```

### Mecânica de Travessia de Vizinhos

Para percorrer todas as arestas que saem de `node_id`:

```rust
let start = row_offsets[node_id as usize] as usize;
let end = row_offsets[(node_id + 1) as usize] as usize;
let outbound_edges: &[EdgeRecord] = &edges[start..end];
```

Esta operação requer **zero alocações em heap** e executa em tempo O(1), entregando uma fatia contígua de memória ideal para o hardware prefetcher da CPU.

## 4. Arquitetura do Bloco Vetorial

O `VectorBlock` armazena representações numéricas densas para cálculo de similaridade semântica. O Graphite suporta dois modos:

### Modo Float32 (Sem Quantização)
* Vetores são armazenados como arrays contíguos de valores IEEE 754 de precisão simples em little-endian.
* **Bytes por Vetor:** `dim * 4 bytes` (ex: `384 * 4 = 1.536 bytes`).

### Modo Quantização Escalar (SQ8 Int8)
* Valores em `[-1.0, 1.0]` são mapeados linearmente em inteiros de 8 bits `[-128, 127]` com parâmetros por vetor de `scale` (f32) e `min_val` (f32).
* **Bytes por Vetor:** `dim + 8 bytes` (ex: `384 + 8 = 392 bytes`).
* **Economia de Memória:** Atinge **3.92x de compressão em disco/RAM** mantendo correlação de similaridade por cosseno `>= 0.999`.

## 5. Pool de Interning de Strings

Descrições de texto, rótulos de nós e nomes de relacionamentos são desduplicados em uma tabela de interning de strings:

1. **Cabeçalho:** 4 bytes armazenando a contagem total de strings `S`.
2. **Índice de Offsets:** `S * 8 bytes`, onde cada entrada contém:
   * `offset: u32` (Offset em bytes no pool de dados)
   * `length: u32` (Tamanho da fatia de bytes UTF-8)
3. **Pool de Dados:** Bytes UTF-8 contíguos sem caracteres nulos de terminação.

Resolver um `StringId(k)` retorna uma fatia de string `&str` com tempo O(1) diretamente emprestada da página mapeada em memória.

## 6. Mapeamento de Memória Zero-Copy (`memmap2`)

O Graphite realiza o mapeamento no nível do kernel através da crate `memmap2`:

```rust
use memmap2::Mmap;
use std::fs::File;

pub struct MmapGraphReader {
    mmap: Mmap,
    header: GraphHeader,
}

impl MmapGraphReader {
    pub fn open(file: &File) -> Result<Self> {
        let mmap = unsafe { Mmap::map(file)? };
        let header = GraphHeader::from_bytes(&mmap[0..HEADER_SIZE])?;
        
        // Verificação de integridade via CRC32
        let computed_crc = compute_crc32(&mmap[HEADER_SIZE..]);
        if computed_crc != header.checksum {
            return Err(GraphiteError::CorruptedChecksum {
                expected: header.checksum,
                found: computed_crc,
            });
        }

        Ok(Self { mmap, header })
    }
}
```

## 7. Garantias de Escrita Atômica

Para garantir a consistência do banco contra falhas de energia ou travamentos durante a gravação:

```text
Estado do Grafo em Memória
       │
       ▼
Cálculo de CRC32 & Offsets das Seções
       │
       ▼
Gravação em Arquivo Temporário (.tmp.uuid)
       │
       ▼
Sincronização de Disco (fsync / flush)
       │
       ▼
Substituição Atômica no SO (syscall rename)
       │
       ▼
Arquivo .graphite Consistente e Íntegro
```

1. Todas as mutações são compiladas em buffers contíguos na memória.
2. O conteúdo completo é gravado em um arquivo temporário irmão (`<target>.tmp.<uuid>`).
3. Uma chamada explícita `fsync` descarrega as páginas do kernel para a mídia física.
4. O arquivo temporário substitui o destino por meio de uma syscall atômica (`rename(2)` em Linux/POSIX, `MoveFileEx` no Windows).
