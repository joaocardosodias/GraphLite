Autonomous AI agents and LLM coding assistants require persistent, long-term memory to maintain architectural context, user preferences, and cross-session constraints. 

Graphite provides a native **Model Context Protocol (MCP)** server (`graphite-mcp`) communicating over JSON-RPC 2.0 stdio, allowing frontier AI models (Claude, GPT-4, Cursor) to retrieve grounded subgraphs, persist memories, and link entities in real time.

---

## 1. Native MCP Tools

The `graphite-mcp` server exposes three primary tools directly to AI models:

| MCP Tool Name | Purpose | Primary Arguments |
| :--- | :--- | :--- |
| `graphite_retrieve` | Context retrieval for questions & prompts | `query` *(string)*, `max_tokens` *(int)*, `top_k` *(int)* |
| `graphite_remember` | Real-time entity & fact persistence | `name` *(string)*, `type` *(string)*, `description` *(string)* |
| `graphite_connect` | Relational edge creation between entities | `source` *(string)*, `target` *(string)*, `relation` *(string)*, `weight` *(float)* |

* **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

## 3. Tool Reference

### `graphite_retrieve`

Executes hybrid semantic search over vectors, BM25, and CSR graph topology, returning formatted Markdown within a designated token budget.

```json
// Example MCP Tool Call by LLM
{
  "name": "graphite_retrieve",
  "arguments": {
    "query": "What are the rules for database atomic writes?",
    "max_tokens": 400,
    "top_k": 3
  }
}
```

**Returned Context:**
```markdown
# Retrieved Knowledge Context:
- [AtomicWriteGuarantees] (Type: ArchitectureRule, Relevance: 0.94)
  Description: All file modifications compile in-memory and write to temporary sibling files before kernel fsync and atomic rename.
- [CsrGraph] (Type: Struct, Relevance: 0.88)
  Description: Immutable compressed sparse row graph topology with zero-copy mmap.

# Structural Relationships:
- AtomicWriteGuarantees --[PROTECTS]--> CsrGraph
```

---

### `graphite_remember`

Stores architectural decisions, user preferences, or system rules with automatic real-time deduplication.

```json
// Example MCP Tool Call by LLM
{
  "name": "graphite_remember",
  "arguments": {
    "name": "StrictMonochromeTheme",
    "type": "DesignRule",
    "description": "User requires strictly pure black and white styling across all frontend documentation pages."
  }
}
```

---

### `graphite_connect`

Connects two existing entities with a directed, weighted relationship.

```json
// Example MCP Tool Call by LLM
{
  "name": "graphite_connect",
  "arguments": {
    "source": "StrictMonochromeTheme",
    "target": "FrontendDocumentation",
    "relation": "MUST_APPLY_TO",
    "weight": 0.98
  }
}
```

## 4. Autonomous Agent Memory Cycle

<Steps>
<Step>
### 1. Context Retrieval Before Action
Before responding to user queries or editing codebase files, the AI agent calls `graphite_retrieve` to ground its context in verified project conventions and architectural rules.
</Step>

<Step>
### 2. Decision Execution & Verification
The agent performs its tasks (code refactoring, answering technical questions, updating schemas) conforming to retrieved graph constraints.
</Step>

<Step>
### 3. Automatic Long-Term Memory Inscription
When a new preference, design choice, or persistent requirement is established, the agent calls `graphite_remember` and `graphite_connect` to ensure subsequent sessions retain full memory continuity.
</Step>
</Steps>
