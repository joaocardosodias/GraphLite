Naive RAG pipelines slice documents into arbitrary fixed-character blocks, often splitting paragraphs mid-sentence and severing critical heading context. Graphite features a **Hierarchical Semantic Chunker** that parses document structures and automatically weaves chunks into an interconnected Knowledge Graph during ingestion.

---

## 1. Hierarchical Semantic Chunking Architecture

Rather than treating text as a flat list of disconnected vectors, Graphite creates a multi-layered relational graph:

```text
[Document Node: codigo_civil.md]
        │
        ├─── [SECTION_OF] ───► [Section Node: Livro III - Do Direito das Coisas]
        │                             │
        │                             └─── [PART_OF] ───► [Chunk Node: Art. 1.228]
        │                                                        │
        │                                                        └─── [NEXT_CHUNK] ───► [Chunk Node: Art. 1.229]
        │
        └─── [SECTION_OF] ───► [Section Node: Livro IV - Do Direito de Família]
```

### Generated Graph Topology

| Node Type | Graph Role | Description |
| :--- | :--- | :--- |
| **`Document`** | Root Node | Represents the file source, path, metadata, and content hash |
| **`Section`** | Intermediate Hub | Represents major headings (`#`, `##`, `###`), organizing topics |
| **`Chunk`** | Leaf / Text Chunk | Bounded text passage (~350 tokens) containing dense embedding |
| **`Entity`** | Named Node | Extracted domain entity (e.g. `Art. 861`, `Struct AuthService`) |

## 2. Multi-Format Parsers

Graphite provides built-in parsers for standard documentation formats:

| Format | Extension | Parser Behavior |
| :--- | :--- | :--- |
| **Markdown** | `.md`, `.mdx` | Heading-aware AST traversal; preserves code blocks and tables intact |
| **PDF Documents** | `.pdf` | Multi-page text extraction with whitespace and header/footer cleanup |
| **Plain Text** | `.txt` | Paragraph boundary detection with token sliding windows |
| **JSON Data** | `.json` | Key-value flattening and property-based entity node generation |
| **CSV Tabular** | `.csv` | Schema-driven entity creation mapping rows to graph nodes |

## 3. Chunker Configuration Options

```rust
// Configuration for semantic chunking
pub struct ChunkConfig {
    pub target_chars: usize,   // Target character size (~1200 chars / ~350 tokens)
    pub overlap_chars: usize,  // Overlap between adjacent chunks (~150 chars / ~40 tokens)
}
```

When ingesting documents via the CLI or REST API:

```bash
graphite ingest ./documents \
  -d knowledge.graphite \
  --chunk-size 350 \
  --chunk-overlap 40 \
  --extensions md,txt,pdf \
  --no-tmp
```

## 4. Content Hash Caching & Watch Mode

To prevent redundant embedding generation on large document sets:

<Steps>
<Step>
### 1. File Fingerprinting
During ingestion, Graphite computes a cryptographic content hash for each document.
</Step>

<Step>
### 2. Cache Validation
When running `graphite ingest` or continuous `--watch` mode, unmodified files are skipped instantaneously (&lt; 1 ms).
</Step>

<Step>
### 3. Differential Graph Update
When a file is modified, its existing chunks and relationships are cleanly purged from the in-memory index before inserting newly generated chunks.
</Step>
</Steps>

## 5. Real-Time Semantic Entity Resolution

During ingestion, newly extracted entity nodes are compared against existing graph entities using vector cosine distance:

```text
cosine_similarity(v_new, v_existing) >= 0.92
```

When a match is detected, Graphite automatically aliases or merges the nodes, linking relationships to the canonical entity instead of polluting the graph with duplicates.
